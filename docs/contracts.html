Build Pledge contract notes

Pledge is a zero-argument, fixed-supply ERC-20. Its constructor mints exactly 1,000,000,000 PLDG (1027 minor units) to its deployer. There is no owner, mint, pause, fee, upgrade, or recovery power.

HabitPledge has one constructor argument: the deployed PLDG address. For the Sepolia ProjectFactory launch this must be $token. The contract has no owner or administrator.

Rules and assumptions

  • A pledge has 1–52 weeks, a non-empty goal, a distinct nonzero beneficiary, and a positive stake evenly divisible by its week count.
  • Week zero begins at the creation timestamp. Each seven-day window is half-open: its start is included and the next window's start is excluded. One check-in is allowed per window and only from the pledger.
  • After the exact end timestamp, anyone can trigger settlement. Each checked week returns one slice to the pledger; each missed week sends one slice to the beneficiary. A fully completed pledge therefore returns the entire stake.
  • Transfers occur only during creation and final settlement. State is updated before external token calls and all mutating entry points share a reentrancy guard. A reverting or false-returning token transfer reverts the whole operation.

Deployment and operations

Target chain is Sepolia (11155111). Deploy Pledge first, then HabitPledge with that address. This contribution does not create launch.json, broadcast transactions, or control keys. The manifest contributor must use the accepted source, order these dependencies, name the application HabitPledge, and pass $token.

There are no operator duties after deployment. Users must approve PLDG before creation; any account may settle an expired pledge. Clients and indexers should monitor all three state-change events and display timestamps using chain time.

Release responsibilities and risks

The publishing, attestation, admission, and deployment services remain responsible for source linkage and launch policy. An independent contributor must adversarially review the accepted contracts and later manifest before release. The seven-day schedule depends on block timestamps, and funds remain locked until the final window ends. Tests are evidence of intended behavior, not a security audit.

Canonical ABI exports are docs/abi/Pledge.json and docs/abi/HabitPledge.json.
